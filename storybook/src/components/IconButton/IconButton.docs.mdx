## Usage guidelines

### When to use

Choose an Icon Button instead of a regular Button when it must align with text.
Match the size of the Icon Button to the surrounding text.

### When not to use

Only [functional icons](/docs/brand-assets-icons--docs#functional-icons) belong in an Icon Button.
For other icons, use a [Button](/docs/components-buttons-button--docs) so that the user can read its label.

Do not use an Icon Button to submit a form; that is a [Button](/docs/components-buttons-button--docs)’s job.
Even the one icon-only submit in the system — the search button — is a Button, not an Icon Button.

### How to use

An Icon Button still needs a label for screen reader users.
Provide it through the `label` prop; it is read aloud even though it is not shown.

## Examples

### On a coloured background

An Icon Button on a coloured background must set [the correct text colour](/docs/brand-design-tokens-colour--docs#pairing-foreground-with-background-colours) to provide enough contrast.
We have light and dark background colours, and Icon Buttons behave differently on each.

#### Contrast colour

Use the contrast colour on a lime, orange or yellow background.
It will make the icon black.

<Canvas of={IconButtonStories.ContrastColour} />

#### Inverse colour

Use the inverse colour on an azure, blue, green, magenta or purple background.
It will make the icon white.

## Design

An Icon Button has no shape of its own: no border, no background, and no padding.
It takes up no more room than the icon it holds, which is what lets it sit inside a line of text without disturbing the line.

The icon is given a square box, so the area that responds to the pointer is a square centred on the icon rather than a shape that follows its outline.
Hovering tints that square with the icon’s own colour at one-eighth opacity instead of filling it, so the affordance appears without the icon shifting or changing weight.

The focus outline is offset from the icon rather than drawn against it, which keeps a thin glyph readable inside the ring.

## Accessibility

An Icon Button renders a `button` element and always writes its label into the markup, hidden visually.
Screen readers announce that label, so the button is never announced as unlabelled, and the icon contributes nothing to the name.

Its `type` defaults to `button` rather than `submit`, so it never submits a form by accident: a close button dismisses a Dialog through its click handler, not by submitting a form the Dialog may contain.
