## Usage guidelines

### When to use

Show an Error Message above a form field that has a validation error.
For guidance and examples on using error messages in a form,
refer to the [Field](/docs/components-forms-field--docs) and [Field Set](/docs/components-forms-field-set--docs) documentation.

Read the documentation by [NL Design System](https://www.nldesignsystem.nl/richtlijnen/formulieren/foutmeldingen) and [Gov.uk](https://design-system.service.gov.uk/components/error-message/) for more information on the contents of error messages and when to show them.

### How to use

#### No rich text

Do not use rich text (such as links or lists) in an Error Message.
Some screen readers, like VoiceOver, skip over rich text when reading out descriptions.
For more information, see [NL Design System](https://nldesignsystem.nl/richtlijnen/formulieren/descriptions/inhoud/).

Connect the Error Message to the input it describes through the input's `aria-describedby` attribute.

### How to write

Explain what went wrong and how to fix it.

## Examples

### Custom prefix

Error messages are automatically prefixed with a visually hidden text, the Dutch word ‘Invoerfout’.
This makes the error message more clear for screen reader users.
If you want to change this prefix, to support another language for example, you can use the `prefix` prop.

## Design

An Error Message is red text with an icon before it, and nothing else: no background, no border, no box.
The [Field](/docs/components-forms-field--docs) around it is what marks the error more heavily, with a red rule along its leading edge, so the message itself can stay quiet.

The icon keeps the message from depending on its colour alone, which is what a reader who does not distinguish red from the text around it needs.

## Accessibility

An Error Message renders a `p` element, so it is read as ordinary text when the field it describes is reached through `aria-describedby`.

It opens with a word that is in the markup and hidden visually — ‘Invoerfout’ by default.
A description read out on its own gives no clue that it is an error, so the prefix supplies the context that the colour and the icon carry visually.

The component does not announce itself when it appears, and it is not a live region.
Announcing it is the job of the field that now describes it, or of an [Invalid Form Alert](/docs/components-forms-invalid-form-alert--docs) at the top of the form.
