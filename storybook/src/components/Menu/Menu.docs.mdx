## Usage guidelines

### When to use

Include this component twice: one in the Page Header and one to the side of the Page.
Set the `inWideWindow` prop to the latter to ensure only one of them is visible, and to get the correct appearance.

This component must only be used in [Compact Mode](/docs/docs-guidelines-modes--docs).

### When not to use

This component must not be used for public websites.
They should offer navigation using the Page Header only.

Do not use this component anywhere other than the Page Header and the side of the Page.

### How to use

Set `expandable` on the wide-window instance when the Menu needs room for a second level of navigation.
It adds a button that widens the Menu, which shows the links in the horizontal layout.
Start the Menu out wide with `defaultExpanded`, or pass `expanded` together with `onToggle` when the parent should own the state.

Use `Menu.Item` for a top-level entry that owns submenu links.
Its `label` names the parent link, and its children are the nested `Menu.Link` items.
In wide windows a Menu with a submenu requires `expandable` to be set, because the submenus are only visible while the Menu is expanded.

### How to write

Use filled icons for top-level links.
Submenu links usually only need text.

## Design

The menu has a blue background.
Links have a white icon and a label.

In a narrow window, the menu occupies the full width.
The icon and label of the link sit next to each other.

In a wide window, the menu has a maximum width of 8rem.
It adds whitespace at the top to align with the baseline of Page Header.
The icon is larger and positioned above the label.

When `expandable` is enabled, the wide Menu shows an icon-only button at the top end.
Its default state keeps the narrow column and the vertical link layout.
Expanded, the Menu is `14rem` wide and the links return to the horizontal layout, with the label next to the icon.
The submenu is visible in a narrow or medium window and in an expanded Menu, and hidden in the narrower column, which has no room for it.
Its links are indented by a small space, so they start at about half the width of the icon of their parent.
Keeping room for the labels matters more there than aligning them with the label of the parent.

In narrow and medium windows the Menu reaches both edges of the window by cancelling the horizontal padding of the Page Header with a negative margin of the same size.
That ties the component to the one context it is used in, which is accepted here: it is the only way for a band of colour to span the window while the links stay aligned with the content around them.
Where that padding grows to clear a display cutout, the margin grows with it, so the blue still runs to the physical edge of the screen while the links move in.

A link is only as wide as its icon and label in the narrow layout, so the area that responds to a click does not extend across the empty space beside the text.
In the wide layout the links do stretch, since the column is barely wider than the labels themselves.

## Accessibility

Without `inWideWindow` the Menu renders a `div`, because it then sits inside the `nav` element of the [Page Header](/docs/components-containers-page-header--docs).
With the prop it renders a `nav` of its own, named by a visually hidden heading that `accessibleName` fills.
A submenu is a nested `ul` inside the parent item’s `li`, so the list structure stays valid without JavaScript interaction.
With `expandable`, the icon-only button is named through `expandButtonLabel` and `collapseButtonLabel`.
The button reports through `aria-expanded` whether the Menu is expanded, which in a Menu with submenus also shows and hides their links.
Without scripting the button cannot work, so it is hidden and the submenus stay visible in the narrow column.

That name defaults to ‘Hoofdmenu’, and so does the `navigationLabel` of the Page Header.
A wide window shows both navigations, so give one of the two another name.
