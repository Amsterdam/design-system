## Subcomponents

A Table is composed of a Caption, a Header containing Header Cells, a Body, an optional Footer, and Rows of Cells.
Caption, Header, Body, Footer, and Row have no props of their own; the example above shows each of them in place.

### Cell

Holds a single value within a row.
Use the `align` prop to align the content to the center or end of the cell.
Apply the same value to all cells in the column and the matching `Table.HeaderCell`.

## Usage guidelines

### How to use

Use [Margin](/docs/utilities-css-margin--docs) or [Prose](/docs/utilities-css-prose--docs) to add vertical whitespace.

Add a caption so users can find and understand the Table without reading its data.
Use a [Heading](/docs/components-text-heading--docs) in it, at the level that fits the document outline.

To place content between the Heading and the Table, keep the Caption but hide it visually, then position the heading and content above the Table.
Do not use ARIA relations; they hurt the Table's semantics (see [this article](https://www.scottohara.me/blog/2019/04/19/tabled-tables.html)).

Keep a Table narrow enough to fit where it is used.
A wider one scrolls sideways in a container that cannot be focused, so its far columns are out of reach for anyone working without a pointer unless the table holds something to tab to.

## Features

A Table wider than the space it sits in scrolls horizontally within its own container, rather than widening the page around it.
That container takes keyboard focus, so someone can scroll it with the arrow keys, not only with a pointer or touch.

## Design

Rows are separated by a single rule beneath each one.
There are no vertical lines, no zebra stripes, and no spacing between cells: the columns are held together by their alignment, so the rules do nothing but mark where one row ends.

Cells align to the top of their row, so the first line of every cell in a row starts level even when one of them wraps over several lines.
Header cells in the head align to the bottom instead, which puts a column label that runs onto two lines directly above the values it names.

The caption is bold and aligned with the start of the table rather than centred over it.
It reads as the title of what follows, in the same place a heading would sit.

In print, a Table is never split across two pages.

## Accessibility

A Table caption creates the accessible name for the Table, announced by screen readers on every encounter.
That is also why ‘How to use’ warns against ARIA relations as a substitute: they name the table without giving it the caption its semantics expect.

A Table that is wider than the space it sits in scrolls inside its own container, and that container cannot be focused.
Someone using a keyboard without a pointer therefore only reaches the columns past the edge by tabbing to a link or a control inside the table, and a table of plain values offers nothing to tab to.
‘How to use’ covers what that asks of a wide table.

The container that scrolls is a focusable group, which keeps the columns past its right edge reachable without a pointing device, as [WCAG 2.1.1](https://www.w3.org/TR/WCAG22/#keyboard) requires.
