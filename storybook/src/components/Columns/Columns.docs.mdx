## Usage guidelines

### When to use

Use Columns for content made of many short parts, such as a long list: the topics in a mega menu or the facilities of a location.
The content uses the width it has, and takes up less height.

### When not to use

To place separate blocks of content side by side, use the [Grid](/docs/components-layout-grid--docs).

### How to use

Choose a `count` that the span of the Cell divides by, so the columns line up with the Grid.
Check that each column stays wide enough for its content, especially in a Cell that spans only a few Grid columns.

Keep one column in a narrow window, unless every part is a word or two, such as the names of the city districts.
More columns leave each part little room there, so a longer part wraps over many lines.

Keep the parts short.
A long one can break across two columns.

The content reads down the first column, then the next.
Sort a list so it can be scanned that way, for example alphabetically.

Small layout glitches in Safari, described under Features, are fine as long as the content stays easy to read.

## Features

By default, Columns shows two columns from the medium breakpoint of the Grid, and one in a narrow window.
A number for `count` sets one to four columns from the medium breakpoint, and keeps one column in a narrow window.
An object sets the number for narrow, medium, and wide windows separately, including more than one column in a narrow window.

The columns end at about the same height.

Safari has two known issues with content in columns.
Content laid out as a grid or with flexbox can have a line cut in half where a column ends.
This includes a [Link List](/docs/components-navigation-link-list--docs), an [Ordered List](/docs/components-text-ordered-list--docs), an [Unordered List](/docs/components-text-unordered-list--docs) and a [Column](/docs/components-layout-column--docs).
And the space between two parts can move to the top of the next column, so that column starts lower than the first.
WebKit tracks them in its bugs about [grid](https://bugs.webkit.org/show_bug.cgi?id=233397), [flexbox](https://bugs.webkit.org/show_bug.cgi?id=78562), and [spacing](https://bugs.webkit.org/show_bug.cgi?id=242313).

## Design

The space between the columns is the same as between the columns of the Grid.
Two columns line up with the Grid in every Cell that spans an even number of Grid columns, which is why two is the default.

## Accessibility

Columns renders a `div`, which adds nothing to the accessibility tree.
It changes how its content is laid out, not the markup.
A list inside stays one list, so its structure reaches assistive technology as [WCAG 1.3.1](https://www.w3.org/TR/WCAG22/#info-and-relationships) requires: a screen reader announces one list with all its items.
Screen readers and the keyboard follow the markup, down the first column and then the next, which is also the order in which the content reads on screen.

In Safari, a link at the top of the second or a later column loses the top edge of its focus outline.
This is a known issue.
WebKit cuts off a shadow in the same way, and [tracks it as a bug](https://bugs.webkit.org/show_bug.cgi?id=14137).
