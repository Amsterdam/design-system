## Subcomponents

The Item, Label, Value, and Actions subcomponents make up a Data List.
An Item groups one label with its value, Label and Value render the `<dt>` and `<dd>` elements, and Actions holds the links or buttons that act on that value.
None of them has props of its own; the examples on this page show them in place.

## Usage guidelines

### When to use

- To show a set of data that a reader checks or scans, such as the details of an object, a case, or a person.
- To let a reader review the answers they gave in a form before they submit it.

### When not to use

- For data that is compared across rows or columns: use a [Table](/docs/components-containers-table--docs).
- For terms and their meanings, such as a glossary: use a [Description List](/docs/components-text-description-list--docs).
- For values to suggest while someone types in a field: despite the name, a Data List is unrelated to the HTML [`datalist` element](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/datalist).

### How to use

Give every item a Label and a Value.
Add Actions only when the reader can change or remove that value, whether that takes them elsewhere or happens in place.

### How to write

Keep labels short and write them without a colon.
Write an action as the change it makes, such as ‘Wijzigen’, and add the label of its item as visually hidden text so the accessible name stays unique.

## Examples

### Orientation

A label and its value sit side by side, and stack as soon as the container gets too narrow for both.
Resize the following example to see the Data List adapt its layout to the available width.

<Canvas of={DataListStories.Orientation} />

### Stacked

Set the orientation to ‘vertical’ to place every value below its label, however wide the container is.
Use this when the values are long, or when the list sits in a narrow column of a wider page.

<Canvas of={DataListStories.Stacked} />

### Actions

An item can offer one or more actions on its value, such as a link to the step of a form where that value is entered or a button that opens a dialog to edit the value directly.
The text, the icon, and the type of each action are yours to choose: pass Standalone Links, Links, or Buttons.

Repeated actions read as a list of identical links to anyone who navigates by links alone.
Add the label of the item as visually hidden text to tell them apart.

<Canvas of={DataListStories.Actions} />

### Composite value

A value takes rich content: several lines of text, an address, a paragraph, a link, or an image.
Its parts are spaced evenly, so an address or a set of photos needs no markup of its own.

<Canvas of={DataListStories.CompositeValue} />

### Header

Introduce a Data List with a Data List Header, which draws a line below its content and sets the space to the list.
Place a [Heading](/docs/components-text-heading--docs) in it, at the level that fits the document outline.
Add at most one action next to it, and use a [Row](/docs/components-layout-row--docs) to place the two side by side.

<Canvas of={DataListStories.Header} />

### Form review

A summary of the answers in a form is an application of Data List rather than a component of its own.
Combine it with an action per item that returns to the matching question, and a button that submits the form.

Group data about several people or subjects by placing a Data List Header above each Data List.
Its action then applies to the whole group, such as removing a person.

<Canvas of={DataListStories.FormReview} />

## Features

Labels and values wrap and hyphenate, so long content stays inside the column instead of overflowing it.
Below the breakpoint every value moves under its label, which keeps a Data List free of horizontal scroll on narrow screens.

## Design

Items are separated by a line, which runs the full width of the list.
The whitespace above and below that line is the same, so the line sits between two items rather than belonging to one.

Several actions sit next to each other, with a thin line between each pair.
They do not wrap onto a new line, so a line never starts a row; in a narrow column their labels wrap instead.

A Data List Header draws a thicker, darker line below its content, and adds space below itself when a Data List follows.

Labels use heading typography and values use body text, which gives the two different line heights.
Side by side, a label therefore gets half of that difference as extra space above it, so its first line sits level with the first line of its value.

By default the column for the labels is at most `15rem` wide.
Set `termsWidth` to `narrow`, `medium`, or `wide` when a ratio between labels and values serves the content better.
Labels and values sit next to each other when their [query container](/docs/utilities-css-query-container--docs) is wide enough (at least `32rem`).

## Accessibility

A Data List renders `dl`, `dt`, and `dd` elements.
These tie each label to its value in the markup instead of only through the layout, which is the kind of relationship [WCAG 1.3.1](https://www.w3.org/TR/WCAG22/#info-and-relationships) asks to be made available.
An Item renders a `div` around one pair, which HTML permits inside a `dl`.

Actions renders a second `dd`, so its links and buttons are announced in the context of the label they act on.
Give repeated actions a unique accessible name with the `ams-visually-hidden` helper, as [WCAG 2.4.4](https://www.w3.org/TR/WCAG22/#link-purpose-in-context) asks.
Use visually hidden text rather than `aria-label`, because browsers do not reliably translate that attribute.

A Data List Header renders a `div`, so it adds no landmark and its Heading stays part of the page outline.
The action in a header applies to the whole group, so give it the name of that group as visually hidden text, such as ‘Verwijderen persoon 1’.
