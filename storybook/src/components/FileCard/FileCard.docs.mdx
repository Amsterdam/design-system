## Usage guidelines

### When to use

Use a File Card for one file that someone selected with a File Input.
Use it for an attachment to a case, a request, or a decision.

### When not to use

Do not use a File Card to link to a web page or to other content that is not a file.
Use a [Link](/docs/components-navigation-link--docs), a [Standalone Link](/docs/components-navigation-standalone-link--docs) or a [Card](/docs/components-navigation-card--docs) for that.

### How to use

Pass the name, and the size and type when they are known.
A File Card takes these as separate values rather than a `File` object, so it works just as well for a file that already sits on a server and has no `File` object at all.
Pass a name that people recognise: the File Card displays it, and its delete button reads it out.
When the stored name is technical, such as a hash, pass a readable one instead.

```tsx
<FileCard name="besluit.pdf" onDelete={remove} size={1536000} type="application/pdf" />
```

`formatMetadataText` returns the whole line below the name, brackets and separator included, so the order of the parts and the punctuation are yours to change.
It receives the size and the type, and the default assumes the type is a media type such as `application/pdf`.
When all you have is an extension, pass a function that formats it:

```tsx
<FileCard
  formatMetadataText={({ size, type }) => {
    const parts = [type, size !== undefined ? `${Math.round(size / 1000)} kB` : undefined].filter(
      (part): part is string => part !== undefined,
    );

    return parts.length > 0 ? `(${parts.join(", ")})` : "";
  }}
  name="besluit.pdf"
  size={1536000}
  type="pdf"
/>
```

Pass other actions, such as a download link, to `actions`.
Pass `onDelete` to add the built-in delete button.
It has no icon, and it always comes after the other actions.
When you ask for confirmation first, remove the file after the confirmation has closed and returned focus to the delete button.

Every action needs the file name in its accessible name, so that someone who lists the buttons on a page can tell them apart.
The delete button adds the name for you, so leave it out of `deleteButtonLabel`.
In your own actions, add it with `ams-visually-hidden`.
A delete button of your own in `actions` needs the name from you too, and it does not move focus after a delete.

Move focus yourself when you remove a File Card that stands alone, the last File Card with a built-in delete button in its list, or the whole list.
Move it to a message that states the file was removed, or to a nearby heading while a status message announces the removal.
Do not move it to the file input, because some browsers go on announcing the file that was removed.

Pass `previewUrl` to show a thumbnail.
The component never creates that address, so whoever creates an object URL also releases it.

## Features

A name too long for its row wraps onto the next line, also when it has no spaces.
When the card is too narrow for the name and the actions side by side, the actions move to a line of their own below.

When a File Card with the focused delete button is removed from a list, focus moves to the delete button of the next file, or of the previous one when it was the last file in the list.
Each File Card must sit in its own list item for this focus move to work.
It moves when the File Card is removed, not when the delete button is clicked, so a cancelled confirmation or a failed delete leaves focus where it was.

## Design

A File Card places a preview of consistent width, the name with its metadata below it, and the actions side by side.
The preview column is the same width whether it holds a thumbnail or the generic document icon, so the names line up down a list.
A thumbnail is shown square, cropped to fill it, whatever the shape of the image.

A long name wraps rather than being cut off with an ellipsis.
The name is what someone recognises the file by, and names that end in a date or a reference – `aanvraag-2026-03-11-definitief.pdf` – lose exactly the part that tells them apart when the end is dropped.
Rows are no longer all the same height as a result, which is the price of a name that stays readable.
Automatic hyphenation is switched off for the name, because a hyphen added at a line break looks like part of the file name.

## Accessibility

The thumbnail is decorative and carries an empty `alt`.
The component cannot know what the image shows, and the name is already beside it, so giving the image that name would only have it announced twice.

When `onDelete` is used, the delete button reads ‘Verwijder’ on screen and ‘Verwijder’ followed by the name of the file to a screen reader.
Repeating the name on screen would put it twice in every row and make the buttons wide and untidy; leaving it out of the accessible name would leave someone reviewing the buttons of a page out of context with the same word for each of them.
Change `deleteButtonLabel` to change both, as the visible label stays the first part of the accessible name.

There is no live region.
Moving focus to a neighbouring button already makes the change noticeable, and announcing it on top of that reads as noise rather than as help.
